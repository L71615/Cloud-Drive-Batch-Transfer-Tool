# 协议规格（Docs-as-Spec）

这里只写**协议事实**，不写代码、不写任何反汇编细节、不写凭据。

规则：

1. 每条结论都要能独立验证——你在浏览器开发者工具里看到的请求/响应，
   或官方公开文档，就是证据。规格里标注「实测于 <日期>」。
2. 字段名照抄接口，不要"顺手改成更优雅的名字"；实现层再做映射。
3. 空着的节就是**未完成**：对应 provider 会抛 `ProviderNotReady`，这是刻意设计。
4. 不写"某软件这么做"，只写"该接口接受 X，返回 Y"。

## 每份规格的固定小节

- §1 登录态：需要哪些 Cookie 字段，怎么判断失效
- §2 请求头：UA / Referer / 必需的客户端标识
- §3 分享校验：分享 ID → 会话 token
- §4 列目录：请求参数、分页、响应字段映射到 `Entry(path,size,digest)`
- §5 转存：请求体、批量上限、成功/重复/超限的返回形态
- §6 目标目录与容量：目录列表、配额
- §7 去重：同名同哈希如何处理
- §8 限速与错误码：哪些要重试、哪些要重新登录
- §9 未知项：还没搞清楚的，写下来，别猜

## 与实现的对应

| 规格节 | 代码位置 |
|---|---|
| §3 §4 §5 | `app/providers/<provider>.py` 的 `API` 字典 + `list_share()/transfer()` |
| §4 字段映射 | `_entries()` |
| §6 | `list_dir()` / `quota()` |
| §8 | `app/providers/_http.py`（重试）+ `base.py`（`ProviderError`/`AuthExpired`） |
